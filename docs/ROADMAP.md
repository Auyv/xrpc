# XRPC 路线图

目标：把 XRPC 整理为一个完整的、可开源的嵌入式 RPC 与订阅发布组件，在串口、USB、CAN、LIN、TCP 等不同链路和总线上提供统一的远程调用和事件通知，并作为今后物联网项目的基座。

| 发布 | 分 0.9.0 和 1.0.0 两步，见发布准备设计。公开仓库 https://github.com/Auyv/xrpc 只含组件、工具和用户文档，测试工程和过程记录留在本地 | 2026-11-03 |
| 原子操作 | **全部移除**，改用节点锁；核心库不含芯片相关代码 | 2026-10-31 |
| 定位 | XRPC 是不依赖硬件的软件应用协议（类比 HTTP/MQTT），链路由适配器负责 | 2026-10-31 |
| 订阅发布 | 订阅关系编译期写死；异步发布；两档投递（是否需要应答）；每次指定等待时长与补发次数；失败回调异常；序号去重；支持观察者；槽位忙时替换；订阅方写明发布方 | 2026-10-31 |
| 总线 | 支持多点总线，无环路；总线上也需要 RPC，用寻址信封实现 | 2026-10-31 |
| 服务发现 | 按微服务的服务发现设计：节点没有的过程，由中间节点到其他链路发现并转发，结果原路带回。取代"第一版不转发" | 2026-11-01 |
| 载荷 | 业务最大约 2500 字节；缓冲区由调用方静态配置，建议各链路配到 2600 字节以上 | 2026-10-31 |
| 起步顺序 | 先建 CLAUDE.md 与项目骨架，再讨论方案 | 2026-10-31 |
| CRC16 | 改为虚接口 `IXrpcCrc16`，算法放到适配层；本机测试先适配成固定值 | 2026-10-31 |
| 内存检查 | 属于集成应用的调试手段，组件不包含 | 2026-10-31 |

完整的订阅发布与总线设计见 `docs/XRPC设计文档.md` 第 11 章。

### 阶段 N1　移除原子宏，改用节点锁　✅
- ✅ 删除 `XRPC_ATOMIC_*` 与 `S32K312.h`；状态读写改为"加节点锁读写"；调用线程等待改为"加锁读、解锁、睡眠"循环
- ✅ 补齐目前未加锁的两处：`XrpcProcessNotifyCallRsp`（由节点层持锁调用）、按节点 ID 查找 peer
- ✅ 文档中写明：多线程使用时 `lock_ops` 必填
- ✅ 消除问题 R4（`Bool` 与 32 位原子宏）、K5
- ✅ 增加真实线程压力测试 `test_threads.c`

### 阶段 N2　链路模型重构　✅
- ✅ 链路增加拓扑属性（`P2P` / `BUS`）与单帧上限
- ✅ 总线链路增加远端节点表（按帧头发送方 ID 区分）
- ✅ 过程静态绑定到链路（总线上可再指定节点）
- ✅ `P2P` 行为与线上字节保持不变，由黄金字节测试守住

### 阶段 N3　调用槽与异步调用　✅
- ✅ 调用槽：序号、截止时间、完成回调
- ✅ RPC 异步版；同步版改为"等待槽完成"的薄封装（启用调用槽时）
- ✅ 启用调用槽后消除"同一过程同一时刻只能一个在途调用"的限制

### 阶段 N4　订阅发布　✅
- ✅ 不需要应答、需要应答 + 补发 + 完成回调 + 异常回调
- ✅ 新增 `0x0120 NotifyEvent`、`0xF120 NotifyAck`
- ✅ 序号去重与缺口上报，观察者，订阅方限定发布方
